# Migration: ninja-build/ninja → cpp-pkg

- **Upstream:** https://github.com/ninja-build/ninja
- **Ref:** tag `v1.13.2` (latest stable release at migration time)
- **Commit:** `3441b633c2fe2c494e958780ba0f4227b1327634`
- **Machine:** macOS arm64, Apple clang 21, cmake 4.4, no `re2c` installed
- **Status:** GREEN — full parity for the posix/macOS configuration; zero
  source patches; one pre-generation step in `pin.sh`

## What the project is

Ninja is a small build system: a single C++11 binary with **no external
library dependencies**, plus a GoogleTest-based test executable and seven
perf/bench executables. Its CMake build is small but exercises several
things cpp-pkg cannot yet express: OBJECT libraries, platform-conditional
source lists, two codegen steps (re2c lexers, `inline.sh` browse-page
inlining), configure checks (`ppoll`, `fork`/`pipe`, compiler-flag probes),
per-source-file properties, IPO/LTO opt-in, a test-only FetchContent
dependency, and an `install(TARGETS)` rule. `GAPS.md` maps each to the
design questions.

## What was migrated

| Upstream target | cpp-pkg target | Notes |
|---|---|---|
| `libninja` (OBJECT lib, 27 common + 2 posix sources) | `libninja` (static-library) | explicit posix source list |
| `libninja-re2c` (OBJECT lib, committed re2c output) | `libninja-re2c` (static-library) | same pre-generated sources CMake uses when re2c is absent |
| `ninja` (binary, browse mode ON) | `ninja` | `browse_py.h` pre-generated by `pin.sh`; `NINJA_HAVE_BROWSE`, `NINJA_PYTHON="python"` |
| `ninja_test` (GTest, 23 sources) | `ninja_test` | googletest v1.16.0 as a cpp-pkg git dependency (`find-package = "GTest"`) |
| 7 × perftest/bench executables | 7 targets | upstream's `foreach` loop, unrolled |
| `install(TARGETS ninja)` | — | **not migrated**: cpp-pkg has no install/export story (GAPS.md) |

Version string: **not** derived by CMake — `src/version.cc` hardcodes
`kNinjaVersion = "1.13.2"` (bumped by hand per RELEASING.md), so no codegen
was needed for it; `--version` parity is automatic.

Deliberate scope reductions (stated, not hidden): Windows/AIX/OS400 source
sets and MSVC flag blocks are unrepresentable without conditional sources,
so this manifest is posix/macOS-only; IPO/LTO (upstream enables it for
Release when supported) was not replicated; `install(TARGETS)` dropped.

## Reproduce

```sh
cd migrations/ninja
./pin.sh                     # clones v1.13.2 into ./upstream, pre-generates
                             # gen/build/browse_py.h, copies CppPkg.toml in
cd upstream
CPPKG_STORE=/tmp/cppkg-store-ninja /path/to/cpp-pkg build
./build/ninja --version      # 1.13.2
mkdir -p /tmp/ninja-testrun && cd /tmp/ninja-testrun   # tests write cwd files
<upstream>/build/ninja_test  # 409 tests
```

No patches: the tree builds unmodified. The only staging step is the
`browse_py.h` pre-generation in `pin.sh` (exact upstream recipe:
`sh src/inline.sh kBrowsePy < src/browse.py > gen/build/browse_py.h`); the
output was verified byte-identical to what CMake's `add_custom_command`
produces.

## Parity evidence (2026-08-14)

Baseline: fresh `cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON`
build of the same checkout (81 edges, GTest via FetchContent because no
system GTest; re2c absent so committed lexers used — same inputs as cpp-pkg).

- `ninja --version`: `1.13.2` from both builds.
- `ninja -t list`: **identical** 16-subtool list from both, including
  `browse` (proves the browse codegen workaround reached the binary).
- `ninja_test` (run from a writable scratch cwd): **409/409 passed from
  31 suites in both builds** (CMake 251 ms, cpp-pkg 279 ms).
- Showpiece: the cpp-pkg-built ninja drove a cpp-pkg build end-to-end.
  `tests/projects/exe-fmt` copied to scratch, `build/` removed, and
  `cpp-pkg build` run with `PATH=<shadowbin>:/usr/bin:/bin` where shadowbin
  holds only our ninja and **no other ninja exists on that PATH**
  (`/usr/bin/ninja`: no such file). cpp-pkg generated `build/build.ninja`,
  invoked `ninja` (ninja_gen.rs runs it from PATH), the build produced
  `exe-fmt`, and the program ran (`fmt version: 110200`, `Hello, world!`).
  fmt came from the store (no cmake on that PATH — a dep rebuild would have
  failed), so this run was also the dependency-cache-hit proof for exe-fmt.
- Our ninja also no-ops CMake's own build dir correctly
  (`ninja -C cmake-build` → `ninja: no work to do.`).
- Store determinism: second and third full `cpp-pkg build` of this project
  (with `build/` wiped) rebuilt no dependency — googletest
  (`googletest-7c9ce38684d2a5bf30da5c28e7b0cd0a`) served from the store;
  adding the consumer-only `-Wno-deprecated` profiles did not invalidate it.
- `CppPkg.lock` pins googletest at
  `6910c9d9165801d8827d628cb72eb7ea9dd538c5` (tag v1.16.0).
- Binary size: 348 KB (CMake, IPO/LTO on) vs 397 KB (cpp-pkg, no LTO) —
  expected delta; behavior identical per the checks above.
- Warnings: upstream's global `-Wno-deprecated` reproduced via per-profile
  `cxx-flags` (repeated four times — see GAPS.md); with it, the cpp-pkg
  build is warning-clean like the CMake one.
